# daily-agenda — מסמך אב (מערכת ניהול יום)

מסמך זה מרכז את **כל ההחלטות והמסקנות** של המערכת. הלוגיקה המלאה ב-`SKILL.md`,
ההעדפות ב-`state/config.md`, והמצב החי ב-`state/current.md`. הכל בריפו +
בטריגרים ברמת החשבון — שורד סגירת שיחה.

## מה המערכת עושה
שגרה יומית אישית מהמייל והיומן: בבוקר מפיקה רשימת עבודה, בערב סוגרת אותה,
והפתוח מתגלגל למחר. בתוספת ניהול משימות יזום, תזכורות אישיות, וארכיון אקסל.

---

## החלטות מקובעות (conclusions)

**שגרה**
- סבב בוקר 07:00, סבב ערב 21:00, ראשון–חמישי, אזור זמן Asia/Jerusalem.
- מקור מיילים: לא-נקראים בתיבה הראשית מ-24 השעות האחרונות (`in:inbox is:unread newer_than:1d`).
- בוקר קורא גם **יומיים קדימה** ומציג "מחר (הצצה)".
- הפתוח מהערב מתגלגל אוטומטית לראש רשימת הבוקר.

**סבב ערב** — מעבר פריט-פריט: בוצע / לא בוצע / בוצע חלקית (+ "מה נשאר").
בוצע חלקית ולא בוצע → מתגלגלים. בוטל → לא מתגלגל.

**משימה מול מידע** — מיילים שדורשים פעולה = משימה. ניוזלטרים/דייג'סטים (נבו
פסיקה/חקיקה/ייצוגיות, זזים וכד') = **מידע**: מוצג עם **תמצית קצרה**, לא נספר
כמשימה, לא מתגלגל, לא באקסל. אפשר לקדם פריט מידע למשימה לבקשת המשתמש.

**ניהול משימות יזום** (בכל רגע)
- "הוסף משימה" / "משימה חדשה" → הוספה.
- "סגירת משימה" / "ביצוע משימה" → סגירה.
- "משימה" בלבד → שאל: הוספה / סגירה / עדכון.
- משימה עם **שעה** → אוטומטית ליומן `relaf6@gmail.com` + תזכורת (30 דק' לפני),
  בלי אישור. **שעה בלבד = היום**; **שעה+יום = אותו יום**. אם עברה — לשאול מועד.

**פרויקט "חותם"** — משימה שמכילה "חותם" → קטע "משימות חותם" (עדיין משימה רגילה).
- "סיכום משימות" = כל המשימות (בלי מידע), טקסט ממוספר בבלוק קוד עם סטטוסים.
- "משימות חותם" = רק קטע חותם. **דלתא כברירת מחדל** — רק מה שהתחדש מאז הסיכום
  הקודם (נקודת-ציון ב-`state/chotam-summary-checkpoint.txt`). טווח מפורש
  (חודש/שנה/תאריך-עד-תאריך) = שאילתה חד-פעמית שלא מזיזה את נקודת-הציון.

**סקירה שבועית** — כל חמישי בבוקר מתווספת משימה "לבחון סטטוס עורכי דין:
אביאור, חדוה, שוהם, טל", + פוש ייעודי.

**יומן** — כל האירועים על יומן אחד: `relaf6@gmail.com`.

**חגים** — משתיקים תזכורות רק בימים האסורים במלאכה (ימים טובים). ערבי חג,
חול המועד, צומות, יום הזיכרון/העצמאות — כן. תאריכים ב-`state/holidays-no-notify.md`
ומוטמעים בטריגרים; לרענן פעם בשנה.

**אקסל** — `state/activity-log.xlsx` (RTL, גיליון "פעילות") = ארכיון קבוע, מקור אמת.
נכתב בכל ערב, שורה לכל פריט (תאריך/יום/קטגוריה/פריט/סטטוס/מה נשאר). נשלח בערב
כקובץ + קישור. מותר לגזום `state/log/*.md` ישנים — לא את האקסל.

**הרשאות** (`.claude/settings.json`) — אישור אוטומטי: עריכות קבצים, git, קריאת
מייל/יומן, יצירת אירועי יומן, ניהול טריגרים. **אישור ידני**: שליחת/מחיקת מייל,
מחיקת/עדכון אירוע.

**פוש** — מגיע לנייד רק כש-Remote Control מחובר + הרשאות התראה פעילות.

## מעבר לשיחה חדשה (הקלה)
הסקיל ב-main, אז **כל שיחה חדשה על הריפו טוענת אותו אוטומטית**. אבל הטריגרים
קשורים לשיחה הנוכחית. כדי לעבור לשיחה קלה: פתח שיחה חדשה על הריפו, אמור
"קשר מחדש את טריגרי daily-agenda לשיחה הזו" — והסקיל ייצור מחדש את הארבעה
מעל הבסיס, קשורים לשיחה החדשה (ואז אפשר למחוק את הישנים).
